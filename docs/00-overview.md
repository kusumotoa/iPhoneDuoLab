# iPhone Duo の基礎

## 前提: 2 台ではなく 1 台

iPhone Duo は、2 つの独立したディスプレイを持つ端末とは考えません。1 つの端末として扱います。開く操作は、アプリのウインドウを横に広げるリサイズと同じです。iOS 27 の Mac の iPhone ミラーリングでのリサイズと同じ仕組みが動いています。

閉じた状態で始めた作業は、開いてそのまま続けられることが想定されています。姿勢ごとに別の UI を作る必要はありません。まず size class による適応レイアウトを作り、その上に垂直バーなど Duo 固有の作法を重ねます。垂直バーは、画面の縦が短いときにステータスバーやツールバーが左右の側面へ移って縦に並ぶ配置です。

### アプリは iPhone アプリのまま

Duo 専用の user interface idiom はなく、`.phone` を返します。新しいのは、内側ディスプレイで水平・垂直ともに regular になる組み合わせが iPhone で初めて現れることだけです。

### 閉じたときにアプリがどうなるか

以下は Group Lab（Apple 担当者に質問できるセッション）での回答です。解説資料経由で、公式ドキュメントでは未確認です。

- 内側ディスプレイで全画面表示していたアプリは、閉じると外側ディスプレイへ移って動き続けます。バックグラウンドへは回りません
- Split View で 2 つ並んでいた場合は、直前に操作していた方が外側へ上がります。もう一方はバックグラウンドへ回ります
- 閉じてすぐ開けば両方戻ります。時間が空くと、外側にいたアプリが内側全体を占めます

破棄と再生成ではなくリサイズなので、標準のナビゲーションコンテナを使っていれば状態はそのまま引き継がれます。

### iPad 版があるアプリ

iPad のデザインは良い出発点ですが、Duo は電話です。iPad にしかない要素は取り除くか、idiom で分けてください。iPad アプリを載せる最初の手順は、ユニバーサル化して対応プラットフォームに iPhone を加えることです。

iPhone Duo だけで動くアプリや、1 つの姿勢しか想定しないアプリは作らないでください。利用者は、製品ラインの 1 機種として扱います。古い OS への対応を続ける場合は、Duo 固有の部分を availability check で囲みます。

## デバイスの構成

| | 外側ディスプレイ | 内側ディスプレイ |
| --- | --- | --- |
| 見える状態 | 閉じているとき | 開いているとき |
| アスペクト比 | 従来の iPhone より横長 | 大きい |

ヒンジと前面カメラの位置が従来機と異なります。前面カメラは外側と内側で別物です（詳細は [04-camera.md](04-camera.md)）。

## size class

`horizontal` だけでなく `vertical` も見ると 3 パターンです。

| 状態 | horizontal | vertical |
| --- | --- | --- |
| 外側ディスプレイ・縦向き | compact | regular |
| 外側ディスプレイ・横向き | compact | compact |
| 内側ディスプレイ | **regular** | **regular** |

内側は向きによらず regular / regular です。内側では、宣言した supported interface orientations に従った回転もしません。宣言自体は尊重されますが、結果としてアプリがスケーリングされます。縦向きのみ対応のアプリでも、内側では regular / regular になります。Split View マルチタスキングでも同様です。

外側ディスプレイの interface orientation は通常の iPhone と同じです。

### 向きではなく幅で判断する

内側で縦横のレイアウトを変えたい場合、向きは environment と trait から取れます。ただし Apple が勧めているのは、利用できる幅で判断する方法です。iPad では横向きのまま幅の狭いウインドウを作れるので、向きと幅は一致しません。幅の判断は分割ビューのようなコンテナに任せます。グリッドなどは実際の幅に合わせます。

## 3 つの状態と 6 つのポーズ

デザイン上考慮する状態は 3 つです。

- closed: 閉じていて外側ディスプレイを使う
- fully open: 完全に開いて内側ディスプレイを使う
- partially folded: 部分的に折った状態。本のように持つ、机に置く、テント型に立てるといった使い方がある

この 3 状態に portrait / landscape の 2 向きを掛けて、6 つのポーズになります。アプリはこの 6 つすべてで基本機能が使える必要があります。

![6 つのポーズ](assets/poses.svg)

| # | ポーズ | 主な特徴 |
| --- | --- | --- |
| 1 | closed / portrait | 外側ディスプレイ。縦が短いのでバーが側面に寄る |
| 2 | closed / landscape | 外側ディスプレイ。さらに縦が短い |
| 3 | fully open / portrait | 内側ディスプレイ。**バーは従来どおり上下に残る** |
| 4 | fully open / landscape | 内側ディスプレイ。バーが側面に寄る |
| 5 | partially folded / portrait | 折り目が画面を上下に分ける |
| 6 | partially folded / landscape | 折り目が画面を左右に分ける。ヒンジ回避が効く |

## 6 ポーズで何が困るか

従来の iPhone は「1 画面・実質 2 向き」でした。iPhone Duo では、同じアプリが動いたまま画面サイズ・size class・safe area・バーの配置が切り替わります。次のような作りは、いずれも壊れます。

- 画面サイズを決め打ちしたレイアウト
- interface orientation での分岐
- `UIScreen.main` の参照
- user interface idiom からの推測

代わりに、size class・layout margins・safe area を基準にして、自由にリサイズできるレイアウトにします。これが基本方針です。

## 優先順位

リソースが限られる場合、Apple はまず次の 2 つに集中するよう勧めています。

1. size class に基づくレイアウト分岐
2. layout margins と safe area insets の正しい取り扱い（特に水平方向）

`ArrangementView`（Duo 向けの新 API）やヒンジ角度の取得といった新 API は、この 2 つの上に乗せる改善です。

## スケジュールと開発環境

| 項目 | 内容 |
| --- | --- |
| iPhone Duo 発売 | 2026-10-23、搭載 OS は iOS 27.1 |
| Xcode 27.1 | 2026 年 9 月中に提供。Duo 対応 SDK と、**姿勢と向きを扱える新しい Device Hub** を含む |
| Xcode 27.2 | 27.2 の OS とともにベータ提供中 |
| デザインリソース | Apple Design Resources に iOS/iPadOS 27 UI Kit（Figma・Sketch）と iPhone Duo のベゼル（Photoshop・PNG） |

フル対応には **iOS 27.1 SDK** でのビルドが必要です。

| ビルドに使う Xcode | 外側ディスプレイ | 内側ディスプレイ |
| --- | --- | --- |
| Xcode 26 | iPhone mini に近い比率、垂直バーが来る側に黒帯 | 同じ比率で中央表示、両側に黒帯。拡大表示はできるが**姿勢の変化には反応しない** |
| Xcode 27（リサイズ対応済み） | — | ほぼ全体を使うが、ステータスバーの下の**側面**に黒帯 |
| Xcode 27.1 | 全画面 | 全画面 |

表示のされ方を見れば、どの SDK でビルドされたかが分かります。実際に並べた比較は [05-before-after.md](05-before-after.md) にあります。

iOS 27 SDK でリンクした時点でリサイズ対応が有効になります。Xcode 27 で従来の表示のまま据え置く方法はない、との回答でした。`UIRequiresFullScreen` は当面尊重されますが、開閉によるリサイズは発生します。ドキュメント上は、すでに非推奨扱いです。

Apple 側も、準備期間が短いことを認めています。発売日にはベストプラクティスに沿った対応を出し、後から改善を重ねる進め方を勧めています。
